# 컨테이너란?

리눅스 커널의 격리 기술(Namespaces, cgroups)을 기반으로 애플리케이션과 모든 종속성(라이브러리, 런타임 등)을 하나로 묶은 경량의 독립 패키지.

## 언제 사용하는가?

주로 다음과 같은 문제 해결과 요구 사항을 위해 사용됨.

1. **환경 불일치 해결**: "내 컴퓨터에서는 잘 되는데, 서버에서는 안 돼요" 방지. (개발=테스트=운영 환경 일치)
2. **신속한 배포와 확장**: MSA(마이크로서비스) 환경에서 서비스별 빠른 생성 및 복제 필요.
3. **효율적 리소스 관리**: 하나의 서버에서 서로 간섭 없이 여러 앱을 고밀도로 실행.

## 기존 가상화 기술과의 차이

위 요구 사항을 기존 기술(VM, 언어 가상 환경)로 해결할 때의 한계와 컨테이너의 차별점.

### 1. vs 가상 머신 (VM)

*기존 문제*: 환경 격리를 위해 VM을 쓰면, Guest OS까지 설치해야 해서 무겁고 느림.

| 구분 | 컨테이너 (Docker) | 가상 머신 (VM) |
| :--- | :--- | :--- |
| **방식** | **호스트 OS 커널 공유** (프로세스 격리) | 하드웨어 가상화 + **Guest OS 설치** |
| **성능** | 가벼움, 초 단위 부팅 (빠름) | 무거움, 분 단위 부팅 (느림) |
| **효율** | 오버헤드 최소화 (CPU/RAM 효율적) | OS 중복 실행으로 리소스 낭비 큼 |

### 2. vs 언어 가상 환경 (Anaconda, venv)

*기존 문제*: `venv`는 Python 패키지만 격리함. OS 레벨의 시스템 라이브러리(C/C++, DB 설정 등) 충돌은 해결 불가.

| 구분 | Docker 컨테이너 | 언어 가상 환경 (venv 등) |
| :--- | :--- | :--- |
| **범위** | **OS 유저랜드 전체** (시스템 라이브러리 포함) | **특정 언어 런타임/라이브러리**만 한정 |
| **이식성** | OS가 달라도 실행 보장 (높음) | 호스트 OS 환경에 종속적 (낮음) |

## Deep Learning 연구 환경 적용 예시

복잡한 딥러닝 환경 구축 시 컨테이너가 주는 구체적인 이점.

* **환경 설정(Dependency Hell) 해결**:
  * *상황*: PyTorch/TensorFlow 버전과 **CUDA/cuDNN 드라이버 버전** 호환성을 로컬에서 맞추기 매우 어려움.
  * *해결*: NVIDIA에서 제공하는 검증된 이미지(`pytorch:xx-cuda11.8`)를 받아 **즉시 실행 가능**.
* **연구 재현성(Reproducibility) 확보**:
  * *상황*: 논문 구현 코드를 공유받았으나, OS나 라이브러리 버전 차이로 내 PC에선 실행 불가.
  * *해결*: **Dockerfile** 하나로 OS부터 라이브러리까지 완벽히 동일한 실험 환경 공유.
* **실험 및 배포 유연성**:
  * *상황*: 학습된 모델을 데모 서버로 옮기거나, 여러 버전의 모델을 동시에 테스트해야 함.
  * *해결*: 학습 환경을 그대로 이미지로 구워 서버에 배포(Serving)하거나, 버전별 컨테이너를 동시 실행하여 비교.

## 핵심 요약

* **격리성**: 리눅스 기술로 완벽히 분리된 환경 제공.
* **이식성**: 어떤 환경에서도 동일하게 동작 ("Write Once, Run Anywhere").
* **경량성**: VM보다 가볍고 빠르며, 가상 환경보다 강력한 격리 제공.
