# Push & Pull 명령어

`push`와 `pull`은 로컬 저장소와 원격 저장소 간의 변경사항을 동기화하는 핵심적인 명령어입니다.

## `git push`: 로컬 변경사항을 원격 저장소에 업로드

`git push` 명령어는 로컬 저장소에서 커밋한 변경사항들을 원격 저장소에 업로드하여 공유하는 역할을 합니다.

```bash
# git push <원격_저장소_이름> <로컬_브랜치_이름>

git push origin master
```

### Upstream 브랜치 설정

매번 원격 저장소와 브랜치 이름을 입력하는 것은 번거롭습니다. `-u` (또는 `--set-upstream`) 옵션을 사용하여 로컬 브랜치가 특정 원격 브랜치를 추적하도록 설정할 수 있습니다. 한 번 설정하면 그 이후에는 `git push`만 입력해도 자동으로 해당 원격 브랜치로 푸시됩니다.

```bash
# 최초 push 시 upstream 브랜치 설정
git push -u origin master

# 이후부터는 아래 명령만으로 push 가능
git push
```

## `git pull`: 원격 저장소 변경사항을 로컬로 가져오기

`git pull` 명령어는 원격 저장소의 최신 변경사항을 가져와 현재 로컬 브랜치와 병합(merge)하는 역할을 합니다. 다른 팀원이 변경사항을 원격 저장소에 올렸을 때, 그 내용을 내 로컬 작업 환경에 반영하기 위해 사용합니다.

```bash
# git pull <원격_저장소_이름> <원격_브랜치_이름>

git pull origin master
```

Upstream 브랜치가 설정되어 있다면 `git pull`만으로도 충분합니다.

### `pull`의 동작 원리

`git pull`은 내부적으로 두 가지 Git 명령을 순차적으로 실행하는 것과 같습니다.

1.  **`git fetch`**: 원격 저장소의 최신 데이터를 로컬의 `.git` 데이터베이스로 가져옵니다. 이 단계에서는 아직 작업 디렉터리의 파일들이 변경되지 않습니다.
2.  **`git merge`**: `fetch`로 가져온 원격 브랜치의 최신 커밋을 현재 로컬 브랜치에 병합합니다.

### 충돌 (Conflict)

만약 원격 저장소와 로컬 저장소의 같은 파일, 같은 부분을 각기 다르게 수정했다면 `pull` 과정에서 **충돌(Conflict)**이 발생할 수 있습니다. 이 경우, Git이 자동으로 병합하지 못하므로 사용자가 직접 충돌 부분을 수정하고 커밋을 완료해야 합니다.
