# 컴파일 및 확인 (Build & Review) 가이드

이 문서는 작성한 LaTeX 소스 코드를 PDF 문서로 변환하는 빌드 과정과 발생 가능한 에러를 해결하는 방법을 설명함.

## 1. 컴파일 도구 (Build Tools)

단순히 `pdflatex` 명령어를 한 번 실행하는 것으로는 상호 참조나 참고문헌이 완벽하게 연결되지 않음. 따라서 자동화 도구인 `latexmk` 사용을 권장함.

### Latexmk의 역할
*   필요한 컴파일 횟수를 자동으로 계산하여 반복 실행.
*   BibTeX/Biber 등 보조 도구 자동 호출.
*   소스 코드 변경 시 자동 재컴파일(Watch 모드).

### VS Code에서의 실행
`LaTeX Workshop` 확장 프로그램을 설치했다면 별도의 터미널 명령 없이 사용 가능함.
*   **단축키**: `Ctrl + Alt + B` (빌드 실행)
*   **자동 빌드**: 파일 저장 시(`Ctrl + S`) 자동으로 빌드 트리거 (설정에 따라 다름).

## 2. 결과물 확인 (PDF Viewer)

빌드가 성공하면 PDF 파일이 생성됨. VS Code 내부 뷰어 또는 외부 PDF 리더로 확인 가능.

*   **VS Code 내부 뷰어**: `Ctrl + Alt + V` (새 탭) 또는 `Ctrl + Alt + J` (현재 탭 옆).
*   **SyncTeX**: PDF의 특정 위치를 `Ctrl + 클릭`하면 해당 소스 코드 위치로 이동, 반대로 소스 코드에서 `Ctrl + Alt + J`를 누르면 PDF 위치로 이동하는 기능.

## 3. 디버깅 (Debugging)

빌드 실패 시 로그(`.log`) 파일이나 터미널 출력을 확인해야 함.

### 주요 에러 유형

#### 1. Undefined Control Sequence
*   **원인**: 정의되지 않은 명령어를 사용함. (오타 또는 패키지 미로드)
*   **해결**: 스펠링 확인 또는 `\usepackage{...}` 추가.

#### 2. Missing $ inserted
*   **원인**: 수식 모드(`$ ... $`)가 아닌 곳에서 수식 기호(예: `_`, `^`, `\alpha` 등)를 사용함.
*   **해결**: 해당 기호를 `$`로 감싸거나, 이스케이프 문자(`\_`) 사용.

#### 3. Overfull \hbox
*   **원인**: 문장이 페이지 여백을 넘어감 (주로 긴 단어나 수식).
*   **해결**: 문장 수정 또는 강제 줄바꿈(`\\`) 활용.

#### 4. Empty bibliography
*   **원인**: `.bib` 파일 경로가 잘못되었거나 인용(`\cite`)된 항목이 하나도 없음.
*   **해결**: 경로 확인 및 본문에 최소 하나의 `\cite` 추가.
