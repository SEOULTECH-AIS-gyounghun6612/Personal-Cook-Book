# 논문 작성 및 관리 가이드

이 문서는 **LaTeX(전문 조판)**와 **Zotero(서지 관리)**를 활용한 효율적인 논문 작성 및 관리 방법을 제안함.

## 1. LaTeX를 이용한 문서 작성

워드프로세서의 한계를 보완하고 내용과 서식을 분리하여 글쓰기에 집중하는 도구.

### [기존 방식의 한계 및 사례]

- **양식 변경의 어려움**: 저널 투고 거절 후 타 저널로 재투고 시, 인용 스타일(`[1]` ↔ `(Author, Year)`)과 다단 편집 양식이 달라 문서 전체를 처음부터 다시 포맷팅해야 함.
- **이미지 배치의 불안정**: 그림 하나를 옮겼더니 문서 전체의 레이아웃이 깨지고, 캡션이 그림과 다른 페이지로 분리되는 현상.
- **수식 입력의 비효율**: 마우스로 복잡한 수식을 입력하느라 시간이 과다 소요되며, 결과물의 심미성이 떨어짐.
- **서식 통일성 붕괴**: 폰트 크기나 들여쓰기를 수동으로 조절하다가 섹션별로 스타일이 미묘하게 달라지는 실수.

### [LaTeX 도입 효과]

- **스타일 일괄 적용**: 클래스(`.cls`) 파일 교체로 저널 양식 즉시 변환.
- **구조적 안정성**: 대용량 문서 및 다수의 시각 자료를 안정적으로 처리.
- **버전 관리**: 텍스트 기반(`.tex`) 파일로 Git을 통한 변경 이력 관리 용이.
- **상세 가이드**: [LaTeX 작성법](./LaTeX/00.%20intro.md)

## 2. Zotero를 이용한 서지 데이터 관리

인용 데이터의 무결성을 확보하고 논문 수집 및 Bib 관리 시간을 단축하는 도구.

### [수동 관리의 한계 및 사례]

- **인용 키 충돌**: 수동으로 `.bib` 파일을 관리하다가 `kim2023`이라는 키를 중복 사용하여, 본문에 엉뚱한 논문이 인용되는 사고.
- **메타데이터 오류**: 저자 이름 철자나 연도를 잘못 입력했을 때, 이를 인용한 모든 논문을 찾아 일일이 수정해야 하는 번거로움.
- **자료 분실**: "분명 다운받았는데" 파일명이 `download_final.pdf`라 찾을 수 없고, 해당 논문의 서지 정보도 어디 적어뒀는지 기억나지 않음.

### [Zotero 도입 효과]

- **Bib 자동화**: [Better BibTeX] 확장을 통한 고유 인용 키 생성 및 `.bib` 파일 실시간 업데이트.
- **통합 관리**: 브라우저 확장을 통한 원클릭 수집 및 PDF/메모 일원화 관리.
- **상세 가이드**: [Zotero 소개 및 설정](./Zotero/README.md)

## 3. LaTeX와 Zotero 연동 워크플로우 (LATTE 템플릿 활용)

연구실 표준 템플릿(LATTE)과 Git의 고급 기능(Orphan Branch & Submodule)을 결합하여, 독립적이면서도 통합된 논문 관리 시스템을 구축함.

- **상세 가이드**: [LATTE 템플릿 및 버전 관리](./LATTE/README.md)

### [워크플로우 개요]

1. **Zotero**: 연구 관련 논문을 수집하고 [Better BibTeX]을 통해 `ref.bib` 파일을 자동 생성 및 유지.
2. **LATTE 템플릿**: 미리 정의된 스타일(`thesis`, `neurips`, `ieee` 등)과 저자 정보 매크로를 활용하여 즉시 작성 시작.
3. **Git 구조 (Paper Bag)**:
    - **통합 관리**: 하나의 메인 리포지토리(`paper_bag`)에서 모든 논문 프로젝트를 서브모듈로 관리.
    - **독립성 보장**: 각 논문은 `orphan branch`로 생성하여, 서로 다른 논문의 커밋 이력이나 파일이 섞이지 않도록 격리.
    - **재사용성**: 공통 스타일 및 리소스는 공유하고, 개별 논문의 콘텐츠만 독립적으로 관리.

### [단계별 진행]

1. **준비**: Zotero에서 참고문헌 수집 및 `.bib` 추출.
2. **시작**: `orphan branch` 생성 후 LATTE 템플릿 적용.
3. **작성**: VS Code + LaTeX Workshop 환경에서 본문 작성 (스타일 파일 자동 로드).
4. **완료**: 완성된 논문 브랜치를 메인 리포지토리에 `submodule`로 등록하여 보관.
